Database & Data Security Model

Session cookies / tokens

HttpOnly, Secure, SameSite=Strict cookies (or short-lived signed JWTs) over HTTPS only; sessions are regenerated on login and expire after inactivity.

Access control

Role-based access (resident / moderator / admin) enforced server-side on every request — residents see only approved reports plus their own; moderators/admins can review the queue. Roles are never trusted from client input in production.

Data minimization & encryption

Only fields the app needs are stored; passwords are hashed with bcrypt/argon2 (never stored in plain text); sensitive columns (e.g. contact numbers) are encrypted at rest, and all traffic is TLS-encrypted in transit.

Injection & abuse protection

Parameterized queries / an ORM prevent SQL injection, all input is validated and length-limited server-side (matching the client-side limits), and rate limiting protects login and report endpoints from brute-force abuse.

Audit trail

Report creation, moderation decisions, and login events are logged with timestamps and actor IDs for accountability, in line with POPIA requirements.
